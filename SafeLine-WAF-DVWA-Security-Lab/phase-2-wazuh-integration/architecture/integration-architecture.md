# Phase 2 — SafeLine WAF → Wazuh SIEM Architecture

## Final Architecture

```text
Kali Linux
    │
    │ Controlled security-testing traffic
    ▼
SafeLine WAF
    │
    ▼
DVWA / Apache
    │
    ▼
SafeLine PostgreSQL
    │
    ▼
Python Exporter
/usr/local/bin/safeline-to-wazuh.py
    │
    ▼
/var/log/safeline/events.json
    │
    ▼
Wazuh JSON Decoder
    │
    ▼
Custom Rule 100100
Level 10
    │
    ▼
Wazuh Dashboard / Alert
```

## Component Roles

### SafeLine WAF

Detects and records web security events generated by traffic reaching the protected application.

### PostgreSQL

Stores SafeLine detection data. The exporter reads new detection records from the SafeLine database.

### Python Log Exporter

The custom exporter connects to SafeLine PostgreSQL, identifies new WAF detection events, converts them into structured JSON, and writes them to the log consumed by Wazuh.

### State File

The exporter uses:

```text
/var/lib/safeline-to-wazuh.state
```

to remember the last event ID it exported. This prevents the same SafeLine event from being repeatedly sent to Wazuh.

### JSON Event Log

The exporter writes structured events to:

```text
/var/log/safeline/events.json
```

### Wazuh JSON Decoder

Wazuh processes the structured JSON event and extracts individual fields for detection and investigation.

### Custom Wazuh Rule

Rule `100100` at Level `10` identifies events where:

```text
source = safeline
```

### Wazuh Dashboard

Provides centralized visibility into the generated security alerts.

## Data Flow

```text
SafeLine Detection
       ↓
PostgreSQL
       ↓
Python Exporter
       ↓
events.json
       ↓
Wazuh JSON Decoder
       ↓
Rule 100100
       ↓
Level 10 Alert
       ↓
Dashboard
```
